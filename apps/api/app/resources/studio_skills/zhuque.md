# 朱雀报告驱动的去 AI 味

给林月半子（LQ）的公众号文章用。`linyuebanzi-humanizer-zh` 管「怎么改写」，这个 skill 管「拿着朱雀报告一轮轮改」的流程：测什么、先改哪段、什么时候停。改写时两个一起用，先加载 `linyuebanzi-humanizer-zh`。

这套流程来自一次真实的四轮修改：第一轮 AI 特征 17%、疑似 83%；第二轮头尾降下来，人工特征过半；第三轮因为改过头，人工特征反而下降。下面每条规则都对应其中一个教训。

## 第 1 步：先做「检测用纯文本」

**不要让用户直接把 Markdown 原稿贴进朱雀。** 朱雀按片段打分，文件头、固定模板、占位符会和正文混在一个片段里，把整段分数拉高。

从文章 Markdown 生成一个 `检测用纯文本.txt`，内容等于读者最终读到的文字：

删掉：
- front matter（`---` 之间的 `slug:` 等）
- 每篇都一样的固定开头语和固定结尾（关注星标、点赞在看那几行）
- `[截图：…]`、`[可补：…]`、`[可选：…]` 这类占位
- `svg-xxx` 动画卡代码块（发出去是图，不是文字）
- Markdown 记号：`#`、`**`、`==`、`> [!QUOTE]`、二级标题里 `| ENGLISH` 的英文副标题

**必须保留：**
- 用户自己写的原话，包括代码块里他发给 AI 的原始提问、引用的他自己的聊天原文。这是全文最像真人的部分，删了人工占比会掉。
- 正文里作为内容出现的符号（比如讲 bug 时提到的 `==`），别被批量替换误删。

生成后通读一遍，检查有没有句子因为删东西而断掉（比如「只发了一句话：」后面空了）。

**每一轮都用同一种形式去测。** 一轮测 Markdown、一轮测纯文本，片段切法不同，分数不可比。

## 第 2 步：读报告

报告是 PDF，用 `pdftotext -layout 报告.pdf out.txt` 取文字。看两样：

- 片段表：每个片段的占比、字符数、AIGC 值。
- 每个片段的原文，对回文章里的具体段落。

朱雀的三档：0–0.5 人工特征，0.5–0.99 疑似 AI，0.99–1 AI 特征。

有上一轮报告时，**按文字内容对比同一段的分数变化，不要按片段序号对比**，每轮切分位置都会变。先确认用户测的是不是纯文本版；如果片段里出现了 `slug:` 或占位符，说明测的还是原稿，先纠正这一点。

## 第 3 步：只改标红的段，按分数从高到低

- 0.9 以上的先改，通常是开头和结尾。
- 0.5–0.9 的第二批。
- **低于 0.5 的段一个字都不要动。** 动了只会引入新的波动。

每段先找结构问题，再看用词。这次被朱雀抓到的结构，按命中率排：

| 被抓的写法 | 例子 | 改法 |
|---|---|---|
| 并列案例排得整整齐齐 | 「有人……一个……还有人……」每个都是 谁+做了什么+一句评价 | 详略不一：一个细说，一个一句带过，一个只说「没细看」 |
| 对仗金句 | 「不一定是……而是……」「前者靠能力，后者靠判断」 | 删掉，或换成一句不对仗的大白话 |
| 粗体小标题 + 解释，连着好几条 | 「**问题一。** 解释……」排成一列 | 只展开一条，其余合成一两句 |
| 段尾总结 | 「单看哪个都不算大事，但……」「这些坑全是……」 | 直接删，让段落停在事实上 |
| 套路过渡句 | 「有句话得先说清楚」「就这么简单」「这个用法值得试」 | 删掉或换成具体动作 |
| 结尾升华 | 「新模型最值钱的是……」 | 落在作者接下来具体要做什么 |

有效的改法只有三种，都不靠堆口语：
1. **详略不齐**，有的段两句就完，有的段多说几句。
2. **停在事实上**，不替读者总结。
3. **放进真实细节**：对话记录或素材里实际出现过的数字、时间、用户的原话。原话直接引用，不要转述润色。

## 第 4 步：三条红线（这次踩过的坑）

1. **不要硬加口语。** 「好嘛」「这玩意儿有点离谱了」「这句我信」这类为了像人而加的口头语，朱雀照样认成 AI。上一轮开头从 0.76 改到 0.92，就是这么来的。
2. **不要用排比制造说话感。** 「谱是它写的，音是它录的，视频也是它剪的」这种三连，本身就是 AI 句式。
3. **不编造经历。** 「中途去倒了杯水」「吃饭的时候」这类用户没说过的生活细节不能写。缺真实细节的地方留 `[可补：……]` 让用户自己填，并在交付时列出来。替用户写了「接下来打算做什么」这类话时，要明说这句是代写的，请他核对。

## 第 5 步：什么时候停

- 同一段最多改两轮。
- 某段改完分数反而升了：**退回上一版的写法**，不要在新写法上继续叠。
- 0.5–0.6 之间是噪声带，每次重测都会上下浮动零点几。剩下的段都落在这个区间时就停手，继续改只会此消彼长。
- 停手后把剩下的两三段原文列给用户，请他用自己平时说话的方式重说一遍，哪怕只改几句。检测器最难判成 AI 的是作者本人的表达习惯，这一步比任何改写都有效。

## 交付

每轮交付三样，文件名带版本号，旧版本不覆盖：
- `文章-vN.md`：改后的 Markdown（给排版用）
- `检测用纯文本-vN.txt`：让用户拿这个去测
- 一张改动表：哪个片段、原来的问题、怎么改的

同时说明：
- 还剩几处 `[可补]` 要用户自己填。
- 哪些句子是代写的判断或计划，需要他确认。
- **不承诺具体分数。** 检测器有误判，正常的真人文章也常有一两段在 0.5 上下。如实说「这几段压了一轮，结果要再测才知道」。

如果分数比上一轮差，先对比两份报告找原因再动手，原因通常是这三个之一：改过头了（见三条红线）、纯文本删多了、两次检测的形式不一样。把原因讲给用户，包括自己造成的那部分。
