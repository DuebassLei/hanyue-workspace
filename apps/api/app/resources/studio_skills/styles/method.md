# 本次风格档：方法论拆解

人设、用词、禁区以主 skill 为准，这一档只管结构、篇幅和取舍。

读者要的是可复用的做法，不是一次性的操作。判断标准是：读完他能把这套东西搬到自己的场景里。

## 结构

- 开头讲这套方法是怎么被逼出来的：一个做不下去的具体局面，以及当时的错误做法。
- 先给全景：这套方法分几步、每步解决什么问题，用一个自然段的顺序说明，不要上来就列清单。
- 然后逐节展开。每一节都必须包含三样东西：这一步做什么、为什么这样做、什么情况下会失效。
- 每节结尾落到一个可执行动作，读者今天就能做的那种。没有动作的一节，删掉。
- 结尾坦诚讲学习成本和最常见的失败方式，不写「希望对你有帮助」。

## 篇幅

3000–5000 字。四到六节为宜，节数多了会稀释。

## 取舍

- 抽象层次要压住：每讲一个原则，必须紧跟一个来自自己项目的具体例子。只有原则没有例子的段落，重写。
- 允许承认边界：「这套方法在团队超过十个人时会失效」。
- 不要为了显得系统而造名词。能用人话讲的，不要起名字。
