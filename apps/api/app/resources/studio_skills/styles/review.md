# 本次风格档：实测测评

人设、用词、禁区以主 skill 为准，这一档只管结构、篇幅和取舍。

读者要的是一个替他花过钱、踩过坑的人给出结论。判断标准是：读完他知道该不该用、什么情况下不要用。

## 结构

- 开头先交代这次为什么测它：从哪个真实需求出发，不是「最近很火」。
- 紧接着亮出结论，一句话说清推不推荐、推荐给谁。把结论放前面，后面才是过程。
- 主体按真实使用顺序走：装/开通 → 第一次跑通 → 高强度用一段 → 撞到问题。
- 中途必须有一次横向对比：跟哪个同类比、在哪个具体维度上强或弱。对比要有同一个任务下的表现，不做参数罗列。
- 结尾给三段：适合谁、不适合谁、如果只用免费额度该怎么玩。

## 篇幅

2500–5000 字。体验过程可以细，参数和功能清单必须压到最短。

## 取舍

- 缺点必须写，而且要给到具体触发条件：「超过 X 条就开始慢」「中文标点会错」。只写「还有点小瑕疵」等于没写。
- 禁止用「总的来说」「综合来看」收场，直接用结论句。
- 收费、额度和限制写具体数字；查不到就写 `[可补：具体价格/额度]`，不要估算。
