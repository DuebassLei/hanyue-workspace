# 创作台重设计文档

> 本文档基于 2026-11-09 的 grill-me 设计审查会话，记录全部决策与实现计划。

---

## 背景

当前创作台存在两个独立模块：

- **StudioView**（文章创作台）：稿件编辑 + AI 助手 + 发布 + 热点灵感
- **MarkCardStudio**（卡片创作台）：Markdown → 图文卡片生成

两者割裂，用户需要在两处重复配置，且各自存在多个交互问题。

---

## 决策总表

| # | 分支 | 决策 |
|---|------|------|
| 1 | 两个创作台的关系 | **打通**：导航层面建立关联，文章可一键转卡片 |
| 2a | 编辑器升级方向 | **tiptap**，支持 WYSIWYG / Markdown 双模式切换 |
| 2b | 编辑器组件架构 | **共用 `<MarkdownEditor>`**，通过 props 注入卡片台专属扩展（分页节点） |
| 3 | AI 助手交互模型 | **双模式**：独立生成面板（写初稿/大纲）+ inline 浮动菜单（润色/改写/摘要） |
| 4 | 发布流位置 | **独立发布页/抽屉**，从创作台分离 |
| 5 | 卡片台右侧面板 | **重组为三 Tab**：风格 / 布局 / 信息 |
| 6 | 保存与版本管理 | **两层分离**：自动保存（防丢失）+ 手动存版本（里程碑） |

---

## 详细设计

### D1：两个创作台打通

**现状问题**
- 文章台和卡片台是完全独立的路由，没有任何入口互相跳转
- 用户在文章台写完内容，无法直接复用到卡片台

**目标状态**
- 文章台正文区顶部工具栏增加「转为图文卡片」按钮，点击后跳转到卡片台并预填 Markdown 内容
- 卡片台顶栏增加「返回文章台」快捷入口（仅在从文章台跳转过来时显示）

**实现方式**
- 路由跳转时通过 `router.push({ name: 'cards-studio', state: { markdown: draftBody } })` 传递内容
- 卡片台 `onMounted` 检查 `history.state.markdown`，若存在则预填编辑器

---

### D2：编辑器升级（tiptap）

**现状问题**
- 原生 `<textarea>`，Markdown 语法符号裸露，无任何渲染反馈
- 两个创作台各自有独立的编辑区，逻辑重复

**目标状态**
- 共用 `<MarkdownEditor>` 组件，底层使用 tiptap
- 支持两种模式切换：WYSIWYG（所见即所得）/ Source（Markdown 源码）
- 卡片台通过 `:extensions` prop 注入自定义分页节点（`---` 渲染为可视分页线）
- 存储格式统一为 **Markdown 字符串**（前端序列化，后端存 text）

**关键 tiptap 扩展列表**

| 扩展 | 用途 |
|------|------|
| StarterKit | 基础格式（H1-H3、加粗、斜体、列表、引用、代码块） |
| Highlight | `==高亮==` 语法 |
| Table | 表格 |
| Image | 图片（含本地图片 base64 插入） |
| `CardPageBreak`（自建） | 卡片台专属，将 `---` 渲染为可视分页线，双击删除 |
| `AiBubbleMenu`（自建） | inline AI 浮动菜单，选中文字后出现 |

**组件 API 草案**

```vue
<MarkdownEditor
  v-model="markdown"           <!-- 始终是 Markdown 字符串 -->
  :extensions="extraExtensions"  <!-- 卡片台传入 CardPageBreak -->
  :toolbar="toolbarConfig"     <!-- 控制显示哪些工具栏按钮 -->
  :enable-ai-bubble="true"     <!-- 是否启用 inline AI 浮动菜单 -->
  placeholder="在这里写..."
/>
```

---

### D3：AI 助手双模式

**现状问题**
- AI 输出区和编辑器割裂，「插入正文」只能追加到末尾
- `constraints` 硬编码 `targetLength: 600`，用户无法调整
- 润色/改写任务没有 inline 能力，体验很差

**目标状态**

**模式一：独立生成面板**（适合「写初稿」「生成大纲」「扩展角度」）
- 保留右侧面板的 AI Tab
- 修复：支持「插入到光标位置」和「替换全文」两种插入方式（移除原来的 append）
- 新增：`targetLength` 字段让用户选择（300 / 600 / 1000 / 自定义）
- 新增：AI 输出区渲染 Markdown 而非纯文本

**模式二：inline 浮动菜单**（适合「润色」「改写」「摘要」）
- 用户在编辑器中选中一段文字，出现浮动工具条
- 工具条展示：润色 / 改写 / 缩短 / 扩展 / 摘要
- 点击后 AI 直接替换选中内容，并支持「撤销」（tiptap history）

**任务分类调整**

| 任务 | 入口 |
|------|------|
| 扩展角度、生成大纲、写初稿 | 独立生成面板 |
| 润色、改写、摘要、缩短、扩展 | inline 浮动菜单（主）+ 生成面板（辅） |

---

### D4：发布流独立化

**现状问题**
- 发布逻辑嵌在创作台右侧 Tab，和写作争夺同一块视口
- `wechatForm.body` 和 `draftBody` 是两份独立数据，用户易发布旧版本

**目标状态**
- 创作台右侧 Tab 移除「发布」Tab，改为顶部工具栏增加「发布」按钮
- 点击「发布」打开全屏抽屉（Drawer），包含：
  - 左侧：文章预览（只读，渲染 Markdown）
  - 右侧：发布配置（账号选择、标题、封面图、发布时间）
  - 底部：「推送到草稿箱」按钮
- 抽屉打开时从当前 `detail` 的最新保存版本读取内容，**不再维护第二份副本**

**数据流变更**
- 删除 `wechatForm.body`、`syncFromDraft`、`scheduleLayout` 等同步逻辑
- 发布抽屉直接读 `detail.versions[0].body`

---

### D5：卡片台右侧面板重组

**现状问题**
- Tab 命名（「底纹与边框」）不直觉，字色控制混在底纹 Tab 里
- 分卡策略放在编辑区而非属性面板
- 顶栏「前后端 API 契约」混入用户操作区

**目标状态**

**三 Tab 重组**

| Tab | 包含内容 |
|-----|---------|
| **风格** | 主题色、背景/底纹/纹理、边框画框、正文颜色、高亮强调色 |
| **布局** | 卡片尺寸、字体选择、字号比例、留白 Padding、**分卡策略**（从编辑区移入） |
| **信息** | 页眉（栏目名/期刊号）、页脚（账号/引导语）、页码显示 |

**顶栏清理**
- 移除「前后端 API 契约」按钮，保留在右侧面板底部 footer（仅开发者需要）
- 顶栏只保留：平台尺寸切换 Tab + 「批量导出图集」按钮

**编辑区清理**
- 移除 `mode-row`（分卡策略行），迁移到布局 Tab
- 修复「插入分页符」按钮：只插入 `\n\n---\n\n`，不附带模板文字
- 新增「插入卡片模板」按钮：插入完整的章节模板文字（原「插入分页符」的实际行为）

---

### D6：保存与版本管理两层分离

**现状问题**
- 无自动保存，浏览器崩溃丢失内容
- 每次手动保存都创建版本记录，版本列表意义模糊
- 版本恢复无 diff，直接覆盖

**目标状态**

**Layer 1：自动草稿保存（防丢失）**
- 编辑内容变化后 debounce 1.5s，自动调用 `PATCH /content/:id/draft`
- 更新 `item.draftTitle` 和 `item.draftBody`（不创建 version 记录）
- 状态显示：`未保存` → `保存中…` → `已自动保存`
- 页面关闭前（`beforeunload`）触发最后一次同步

**Layer 2：手动存为版本（里程碑）**
- 按钮改名为「存为版本」，点击后弹出小弹窗，输入版本备注（可选）
- 调用现有的 `POST /content/:id/versions`，`sourceType: 'manual'`
- 版本列表显示备注，无备注则显示时间戳

**后端接口变更**

```
新增：PATCH /content/:id/draft
Body: { title, body }
作用：更新草稿字段，不创建版本记录
返回：{ updatedAt }
```

## 连带影响

| 影响项 | 说明 |
|--------|------|
| 存储格式 | `draftBody` 统一存 Markdown，tiptap 序列化/反序列化在前端处理 |
| 后端新接口 | `PATCH /content/:id/draft`（自动保存），其余接口不变 |
| 发布流 | 删除 `wechatForm` 副本逻辑，发布抽屉读最新版本 |
| 路由 | 新增发布抽屉路由（或用 query param `?publish=1`），卡片台支持接收 `history.state.markdown` |

---

## 实现优先级

> 按从易到难、独立可验证原则排序

| 优先级 | 任务 | 估计复杂度 |
|--------|------|-----------|
| P0 | 后端 `PATCH /content/:id/draft` 接口 | 低 |
| P0 | 文章台前端自动保存逻辑（debounce + 状态显示） | 低 |
| P1 | 卡片台右侧面板 Tab 重组 | 中 |
| P1 | 卡片台顶栏清理 + 编辑区按钮修复 | 低 |
| P2 | tiptap `<MarkdownEditor>` 组件搭建 | 高 |
| P2 | AI inline 浮动菜单 | 高 |
| P3 | 发布流独立抽屉 | 中 |
| P3 | 两个创作台打通（转卡片入口） | 低 |
