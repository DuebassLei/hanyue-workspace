个人使用与模型方案

简化账户管理，保留模型配置与可靠调用

版本：讨论稿 2.0　｜　状态：供审阅，未实施

范围项目现状账户与安全模型策略实施建议

一、当前方向

以个人使用为主。优先保障现有创作功能稳定运行，减少不必要的外部服务和运营系统。
  • 暂不考虑：积分、创作扣费、充值与会员。
  • 暂不接入：真实邮箱验证码和短信验证码服务。
  • 暂缓：邀请奖励、公开运营相关的活动和商业化能力；未来需要时重新评估。
  • 继续关注：账号安全、个人模型配置、固定模型及异常时的可控切换。

是否彻底关闭所有创作页面的模型选择，以及固定模型和自动切换的具体交互，仍待确认；个人使用不必预设平台共享模型池。

三、个人账户与安全

  • 保留现有邮箱密码登录；邮箱只是登录标识，不代表已验证所有权。
  • 建议个人部署在完成初始账号创建后关闭公开注册，并确认开发态登录已关闭；实际开关和值应先检查部署配置，再决定是否修改。
  • 初始部署需要保留首个账号创建路径。现有注册逻辑对无密码账号的首次部署有特殊处理，因此不要仅凭关闭注册开关就假定初始化入口已完全不可用。
  • 使用强密码，妥善保管 API 密钥与数据库备份；如果通过公网访问，配置 HTTPS 和访问限制。
  • 不依赖真实邮箱时，应提前规划账户恢复及备份方式；不要假设可以通过邮件找回密码。

部署安全建议不代表已检查或修改当前实际配置。个人使用也不自动免除适用的部署、数据保护与服务商条款要求。

四、模型配置与调用策略

保留个人账户下的模型连接，按文本、图片等能力配置。是否在创作页面直接选模型，可按个人习惯决定，不为商业化重构管理体系。

策略建议语义
自动优先默认模型，在合适的失败条件下尝试兼容的备用模型。
固定只使用指定模型，失败时明确提示，不自动切换。
首选加备用如有需要，再单独提供：优先指定模型，允许按配置切换。与严格固定区分。

自动切换仅应发生在能力兼容的候选之间；内容安全拒绝或参数错误不应通过更换模型绕过。流式响应输出后不宜静默拼接其他模型结果。超时不代表上游未执行，生图等异步任务应先查询状态，避免重复请求和额外费用。

上游仍可能按其服务协议收费；建议在管理界面记录实际使用模型、失败原因、尝试次数和可获取的用量，但当前调查的文本路径并未确认完整真实 token 统计。

五、建议推进顺序

  1. 检查实际部署配置：确认注册开关、开发态登录、初始账号及公网暴露情况，不改变现有配置前先确认。
  2. 梳理文本、生图和其他常用创作入口的模型选择、固定与故障切换行为。
  3. 依据个人需求确定是否隐藏创作页选择器，以及各类任务采用自动、固定或首选加备用。
  4. 仅针对确认的缺口制定修改计划和测试：模型失效、无备用模型、首字后失败、超时重复请求、权限与密钥保护。

待确认

  • 生图、小说等功能是否也需要自动切换，还是首期只处理文本？
